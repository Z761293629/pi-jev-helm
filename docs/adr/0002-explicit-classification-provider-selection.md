# Select the Classification Provider explicitly without fallback

Pi Jev Helm gains a second path to Jev — the TypeSafe Jev Client alongside the OpenRouter Jev Client beneath the single Classification Provider — and resolves the choice through an explicit `classificationProvider` field in `pi-jev-helm.json` (`openrouter` | `typesafe`, default `openrouter`) rather than by auto-detecting whichever credential Pi happens to hold, even though auto-detection would have avoided a schema change: routing behavior that silently depends on ambient credentials is surprising, hard to test, and impossible to pin, which contradicts the project's explicit-and-configurable stance. A selection whose credential is missing leaves Automatic Routing unavailable exactly as the OpenRouter-only behavior did; Helm never silently substitutes the other Jev Client, because hidden fallback chains make "why didn't it route?" unanswerable. The schema addition ships in `0.2.0` with migration notes under the Public Preview contract rather than masquerading as a `0.1.x` patch.
