# Select the Classification Provider explicitly without fallback

Pi Jev Helm gains a second path to Jev — the TypeSafe Jev Client alongside the OpenRouter Jev Client beneath the single Classification Provider — and normally resolves the choice through an explicit `classificationProvider` field in `pi-jev-helm.json` (`openrouter` | `typesafe`, default `openrouter`) rather than by auto-detecting whichever credential Pi happens to hold: routing behavior that silently depends on ambient credentials is surprising, hard to test, and impossible to pin. A user may explicitly supersede that configured choice for the current Helm session with a Session Classification Provider Override; the override resets whenever the session begins anew, never rewrites configuration, and affects only future classifications so an in-flight Routed Run remains attributable to the Jev Client that actually started it. Neither selection source permits fallback: setting an override without its credential is rejected, clearing an override may restore an unavailable configured selection with a warning, and any selected Client that later becomes unavailable leaves Automatic Routing unavailable; the schema and additive command ship in `0.2.0` with migration notes under the Public Preview contract.
